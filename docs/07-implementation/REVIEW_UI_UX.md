# مراجعة واجهة وتجربة استخدام H93Lab Center

تاريخ المراجعة: ٨ سبتمبر ٢٠٢٦. النطاق: النسخة المحلية الحالية، مراجعة فقط دون تعديل التطبيق أو البيانات أو تشغيل بحث أو طلب ذكاء اصطناعي جديد.

الواجهة متماسكة بصريًا وتعرض بيانات حقيقية، لكن مسار اتخاذ القرار ومراجعة التغييرات ما زال يحتاج استكمالًا. أهم الأولويات: إصلاح التنقل بلوحة المفاتيح على الموبايل، عرض التوصية والثقة في القوائم، وربط تفسير الدرجة بأدلته. نجاح عرض الصفحات لا يعني اكتمال متطلبات التجربة.

## طريقة التحقق وما نجح

استُخدمت جلسة متصفح مستقلة باسم `ui-review` مع حساب المالك المحلي، دون عرض بيانات الدخول. تمت مراجعة مواصفات الواجهة وسير العمل والمهام ذات الصلة، ثم فحص الصفحة والكود لتحديد أسباب النتائج.

- تسجيل الدخول والتنقل الأساسي يعملان، ولم يسجل المتصفح أخطاء تشغيل أثناء المراجعة.
- خط التطبيق الفعلي هو Cairo Variable. الثيمان الفاتح والداكن يعملان.
- تمت المعاينة عند عرض ١٢٨٠ بكسل، و٧٦٨ بكسل، و٣٩٠ بكسل، وفحص ضيق عند ٣٢٠ بكسل.
- درجة الفرصة وثقة البحث منفصلتان في صفحة الفكرة، وشرح الأوزان والمساهمة الحسابية متاح.
- صفحة مراجعات المستخدم تعرض بوضوح عدم وجود عينة، ولا تختلق نسبًا.
- المستندات والإصداران المنشوران متاحان للقراءة، والنشر الحالي لا يتيح تحرير المستند مباشرة.
- معاينة الشاشة وحالة انقطاع الاتصال تعملان. هذه محاكاة داخل النموذج، وليست إثباتًا لعمل التطبيق كله دون اتصال.

### ١. أولوية عالية — التركيز ينتقل إلى قائمة الموبايل المخفية

**عيب مرصود:** على عرض ٣٢٠ بكسل، بعد فتح `/ideas` والضغط على Tab مرة واحدة، انتقل التركيز إلى رابط الشعار خارج الشاشة عند `x=-245` و`right=-1`. القائمة المغلقة مخفية بتحويل موضعها فقط وتظل قابلة للتركيز. زر البحث أصبح بلا اسم متاح في شجرة الإتاحة عند إخفاء النص على الموبايل والتابلت. كذلك نافذة شرح الدرجة لا تربط عنوانها بعنصر الحوار عبر `aria-labelledby`.

**الأثر:** مستخدم لوحة المفاتيح وقارئ الشاشة قد يتنقل بين عناصر غير مرئية ولا يعرف وظيفة زر البحث أو اسم الحوار.

**التوصية:** تعطيل التركيز والتفاعل مع القائمة وهي مغلقة، واستخدام درج حوار يضبط التركيز عند الفتح ويعيده عند الإغلاق، وإضافة اسم ثابت لزر البحث وعنوان برمجي للحوارات. استكمال نمط التبويبات بأسهم الاتجاهات وارتباط اللوحة بالتبويب؛ الكود الحالي يعرّف أدوار التبويب دون هذا السلوك.

**التحقق بعد الإصلاح:** يبدأ Tab بعنصر مرئي عند إغلاق القائمة؛ لا يتسرب التركيز خلف الدرج؛ يعلن قارئ الشاشة اسم البحث والحوار؛ تعمل الأسهم بين التبويبات.

### ٢. أولوية عالية — مكتبة الأفكار لا توفر أدوات المقارنة والفرز الأساسية

**نقص وظيفي مرصود:** `/ideas` يعرض أعمدة عامة للاسم والسياق والحالة والتاريخ. لا يظهر فيه رقم الدرجة أو الثقة أو توصية النظام. فكرتان مقتولتان تظهران بحالة «غير محسوم» باعتبارها قرار المستخدم، بينما الفكرة المحوّلة لمشروع تظهر بحالة «انطلق». السياق يظهر شرطة لجميع الأفكار. لا توجد أدوات فرز أو فلاتر للسوق أو النوع أو التوصية أو الثقة، ولا اختيار للمقارنة؛ المتاح بحث نصي وترقيم صفحات فقط.

**الأثر:** لا يمكن اتخاذ قرار من القائمة، كما يمكن الخلط بين قرار المستخدم وحكم النظام. يلزم فتح كل فكرة منفردة مع نمو المكتبة.

**التوصية:** إضافة أعمدة منفصلة لتوصية النظام وقرار المستخدم والدرجة والثقة والسوق؛ وفرز وفلاتر محفوظة في الرابط. إضافة المقارنة المحدودة التي تنص عليها المواصفات، مع نسخة بطاقات مختصرة للموبايل.

**التحقق بعد الإصلاح:** تظهر حالة القتل في القائمة حتى لو ظل قرار المستخدم غير محسوم، ويمكن الوصول إلى الأفكار القابلة للبناء وترتيبها دون فتح كل سجل.

### ٣. أولوية عالية — شرح الدرجة لا يصل المستخدم إلى الدليل ولا يوضح اتجاه المنافسة

**نقص مرصود:** نافذة شرح درجة FamilySync تعرض القيمة والوزن والمساهمة والتبرير، لكن عدد الروابط داخلها صفر؛ لا يمكن فتح أدلة العامل أو الادعاءات منه. العامل المسمى «المنافسة» يعرض ٨٠ ومساهمة موجبة ٤، بينما تبريره يصف منافسة قوية من تطبيقات راسخة. المواصفة تعرفه باسم جاذبية المنافسة، ولذلك يصعب معرفة ما إذا كان ارتفاع الرقم جيدًا أم سيئًا. هذه الملاحظة تثبت التباس العرض والعقد، ولا تجزم وحدها بأن الصيغة الحسابية خاطئة.

**الأثر:** المستخدم يرى تفسيرًا نصيًا ولا يستطيع تدقيقه بسرعة، وقد يفهم اتجاه العامل بالعكس. معايير القتل مخفية في تبويب المخاطر، رغم أن المواصفة تطلب بقاء ملخصها ظاهرًا دائمًا. جدول درجات الأسواق العالمية والمحلية غير موجود في صفحة الفكرة الحالية.

**التوصية:** روابط من كل عامل إلى الادعاء والمصدر وتاريخ الجمع، وإظهار درجة التحقق والمعلومات الناقصة، وتسمية العامل «جاذبية المنافسة» مع شرح اتجاهه. تدقيق عقد الذكاء الاصطناعي ليطابق الاتجاه. إضافة ملخص قتل ثابت وجدول الأسواق حين تتوفر البيانات، مع حالة واضحة عند عدم توفرها.

**التحقق بعد الإصلاح:** يستطيع المستخدم تتبع أي مساهمة في الدرجة إلى مصدرها، ويفهم معنى الرقم الأعلى، ويرى مانع القتل دون تبديل التبويب.

## حدود المراجعة وخطوة التنفيذ المقترحة

هذه مراجعة خبير مع معاينة فعلية، وليست دراسة مستخدمين ولا تدقيق WCAG كاملًا. لم تُختبر نسب تباين جميع الحالات آليًا، ولا قارئات شاشة فعلية، ولا انقطاع الشبكة الحقيقي، ولا استيراد Figma. لم تُنفذ عمليات مدفوعة أو تعديل إعدادات أو قرارات أفكار أو مستندات. تغييرات الثيم والبحث وحالة النموذج اقتصرت على جلسة المتصفح المستقلة.
