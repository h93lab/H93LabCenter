# Decision workspace and owner research import

Approved scope: the owner requested implementation of the review recommendations on 2026-09-08. This addendum defines the previously unspecified manual validation/import behavior before implementation. It supplements FR-EVD-001/005, FR-SCR-003/004, Workflow 2, Manual Refresh, and TASK-014/025/027/032/035/045.

- Decision lists and comparisons use a recommendation and its referenced score/confidence snapshots, never independently selected latest values. Filters and sorting apply before database pagination. A comparison contains two or three concepts; unstudied markets remain absent. Differences in market, dates, or scoring model are visible.
- Requested research market and observed source market/storefront are separate provenance fields. Apple GLOBAL collection is an explicitly labelled US sample. Unproven language is `und`; neither locale nor programming language establishes human text language. Legacy evidence retains its original immutable content and is visibly labelled legacy/unconfirmed coverage.
- An owner can refresh one existing concept within a stated run budget. The refresh preserves prior research and published blueprints and analyzes the selected concept rather than generating unrelated concepts.
- Manual validation records contain question, method, success criterion, time/cost estimate, outcome (`planned`, `supported`, `rejected`, `inconclusive`), short result, evidence references, and date. They are owner-reported research notes, not independently verified facts and not automatic score overrides. Completed outcomes require a result and at least one owned evidence reference. Records are appended; corrections create a new record rather than rewriting a past result.
- Review import accepts a bounded CSV/JSON file with explicit source name/URL, platform, market, language (or `und`), sample collection timestamp, and confirmation that it contains actual reviews the owner may use. Preview shows parsing/duplicate counts and sample excerpts before persistence. Required row fields are `external_id`, `text`, `published_at`, `url`, `app_id`; optional fields are `title`, `rating` (0–5). JSON must be an array of these objects. CSV must have these header names and uses normal quoted CSV escaping.
- Imported reviews retain user-provided provenance and `verification_origin: owner_import`. They must not be labelled independently verified or representative of all users. Fixtures/sample data are not accepted as live imports. The confirmation is an owner attestation, not automatic proof of authenticity. No purchase, crawling, external messaging, or provider authentication is performed.
- Repeated imports deduplicate by source/platform/market/external identity and content, persist immutable evidence plus review items, and link those items to the selected concept. A later scoped research can consume those explicit links. Import itself does not call AI or change scores.
- New tables use owner RLS with authenticated read access only. Validated authenticated server endpoints perform writes. Budgets, idempotency and published-version immutability remain mandatory.

Acceptance: provenance tests cover GLOBAL→US and unknown language; decision tests cover snapshot pairing/filter-before-pagination; comparison shows unknowns and source/date; import parser rejects malformed/oversized/fixture input, deduplicates retries and respects owner boundaries; manual validations require evidence for completed outcomes; scoped refresh preserves concept identity and published versions. Existing dark/light and mobile behavior remains required.

Apple RSS is treated as a best-effort public source, not a guaranteed competitive-review API. The supported Apple developer API covers reviews of apps accessible to the developer account; it is not assumed to supply arbitrary competitor data. See [Apple customer reviews documentation](https://developer.apple.com/documentation/appstoreconnectapi/customer-reviews). Empty/restricted feeds remain visibly empty/restricted; the owner import is a separate provenance-labelled path.
